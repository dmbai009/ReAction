# Безпека

Re:Action — навчальний (дипломний) проєкт. **Не розгортайте його в публічному доступі без виправлення наведених нижче проблем.**

## Відомі проблеми

| # | Проблема | Де | Наслідок |
|---|---|---|---|
| 1 | Markdown рендериться через `\| markdown \| safe` без санітизації HTML | `blog/templates/post.html`, `home.html` | збережений XSS: автор статті може вбудувати довільний `<script>` |
| 2 | Немає захисту від CSRF | усі POST-форми | сторонній сайт може від імені користувача видаляти статті, ставити лайки, коментувати |
| 3 | `SECRET_KEY` записаний у коді | `blog/__init__.py` | можлива підробка сесійних cookie |
| 4 | Запуск з `debug=True` | `app.py` | інтерактивний відладчик Werkzeug дозволяє виконувати код на сервері |
| 5 | Немає валідації при реєстрації | `blog/auth.py` | дубль імені / email або порожній пароль спричиняють помилку 500 |
| 6 | Редирект на `request.referrer` | `blog/posts.py` (`like_action`) | заголовку Referer не можна довіряти |
| 7 | Немає обмеження частоти запитів на вхід | `blog/auth.py` | можливий підбір паролів |

## Рекомендовані виправлення

1. Санітизувати HTML після Markdown (наприклад, `bleach` / `nh3`) або вимкнути сирий HTML.
2. Підключити `Flask-WTF` (`CSRFProtect`) і додати `csrf_token` у всі форми.
3. Читати `SECRET_KEY` зі змінної оточення.
4. Керувати debug-режимом через змінну оточення, у продакшні запускати через WSGI-сервер (gunicorn / waitress).
5. Перевіряти унікальність і довжину полів при реєстрації.
6. Дозволяти редирект лише на внутрішні URL.
7. Додати rate limiting (`Flask-Limiter`).

## Повідомлення про вразливості

Репозиторій приватний. Про знайдені проблеми повідомляйте власнику репозиторію напряму, а не у відкритих issue.
