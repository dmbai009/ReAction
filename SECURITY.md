# Безпека

Re:Action — навчальний (дипломний) проєкт. Основні проблеми безпеки виправлено, але перед розгортанням у публічному доступі перегляньте розділ «Відкриті питання».

## Що зроблено

| Захист | Реалізація |
|---|---|
| XSS через Markdown | HTML після Markdown санітизується `nh3` (білий список тегів і атрибутів; `<script>`, обробники подій і `javascript:`-посилання видаляються). Уривки на списках статей — plain text |
| CSRF | `CSRFProtect` (Flask-WTF) для всіх POST-запитів; токен у кожній формі; cookie сесії з `SameSite=Lax` |
| Секретний ключ | `SECRET_KEY` береться зі змінної оточення / `.env`; якщо не задано — генерується випадковий ключ на час роботи процесу |
| Debug-режим | вимкнено за замовчуванням, вмикається лише через `FLASK_DEBUG=1` |
| Реєстрація | перевірка формату імені й email, мінімальна довжина пароля (8), унікальність імені та email без урахування регістру |
| Вихід | лише POST-запитом з CSRF-токеном (сторонній сайт не може розлогінити користувача посиланням) |
| Відкриті редиректи | `?next=` після входу та `Referer` після лайку приймаються лише для адрес цього сайту |
| Цілісність даних | унікальні індекси на лайки (користувач + стаття) та взаємодії (користувач + стаття + тип) |
| Пошук | символи `%` і `_` у запиті екрануються |
| Залежності фронтенду | версії бібліотек на CDN зафіксовані |

## Відкриті питання

- **Немає обмеження частоти запитів** на вхід і реєстрацію — можливий підбір паролів. Рекомендовано `Flask-Limiter`.
- **Бібліотеки з CDN без Subresource Integrity** (`integrity`-атрибута). Компрометація CDN дозволила б підмінити скрипти.
- **Немає Content-Security-Policy** та інших захисних заголовків (`Flask-Talisman`).
- **Немає підтвердження email** і скидання пароля.
- Для продакшну використовуйте WSGI-сервер (gunicorn / waitress) за HTTPS і встановіть `SESSION_COOKIE_SECURE=True`.
