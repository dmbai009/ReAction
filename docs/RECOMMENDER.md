# Модуль рекомендацій

Файл: [`recommender.py`](../recommender.py). Підхід — **контентна фільтрація** (content-based filtering): статті порівнюються за текстом, а не за поведінкою інших користувачів.

## Представлення статей

1. Для кожної статті береться рядок `title + " " + content`.
2. `TfidfVectorizer` (scikit-learn, параметри за замовчуванням) перетворює корпус усіх статей на розріджену матрицю TF-IDF: кожне слово отримує вагу, яка росте з частотою слова в статті і падає з частотою слова в усьому корпусі.
3. Близькість двох статей — **косинусна подібність** їхніх векторів (від 0 до 1).

## `get_recommendations(current_post, all_posts, num_recommendations=3)`

Блок «Схожі статті» на сторінці `/post/<id>`.

1. Будує TF-IDF-матрицю по всіх статтях.
2. Рахує косинусну подібність поточної статті з усіма іншими.
3. Сортує за спаданням, пропускає саму статтю і повертає топ-3.

## `get_user_recommendations(user_history_posts, all_posts, num_recommendations=10)`

Стрічка «Рекомендовані» (`/?feed=recommended`).

1. Історія користувача — статті з таблиці `UserPostInteraction` (перегляди та лайки) — збирається в `blog/main.py`.
2. **Профіль користувача** = середнє арифметичне TF-IDF-векторів статей з історії.
3. Рахується косинусна подібність профілю з усіма статтями.
4. Повертаються 10 найближчих статей, яких немає в історії.

Якщо історія порожня, стрічка порожня і користувач бачить підказку почитати або вподобати кілька статей.

## Обмеження поточної реалізації

- **Перенавчання на кожен запит.** TF-IDF будується заново при кожному відкритті статті та стрічки. Для десятків статей це непомітно, але час росте лінійно з розміром бази; `get_recommendations` до того ж рахує повну матрицю N×N, хоча потрібен один рядок.
- **Вага лайків не працює.** `main.py` дублює ID вподобаних статей, щоб лайк важив утричі більше за перегляд, але запит `Post.id.in_(...)` повертає кожну статтю один раз, тож усі взаємодії мають однакову вагу.
- **Знятий лайк лишається в історії** — запис `UserPostInteraction(type='like')` не видаляється.
- **Мова.** Токенізатор за замовчуванням не робить стемінгу і не має стоп-слів для української, тож різні форми одного слова («стаття», «статті») рахуються як різні токени.
- **Холодний старт.** Новий користувач без історії не отримує рекомендацій.
- Теги та автор у векторизації не враховуються.

## Можливі покращення

- Кешувати TF-IDF-модель і перебудовувати її лише при зміні статей.
- Реалізувати ваги взаємодій через зважене середнє замість дублювання ID.
- Додати стоп-слова та лематизацію для української (наприклад, `pymorphy3`).
- Враховувати теги як окремі ознаки; для холодного старту показувати популярні статті.
- Гібридний підхід: додати колаборативну фільтрацію за даними лайків.
